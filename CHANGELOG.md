## [Unreleased]

### Added
- **Oração 24h › Importar planilha: check the names against the directory** — before importing, each name of the sheet is looked up in the member directory (only members of the churches the list accepts). A clear match is linked automatically; a new **Cadastro** column shows who it is, lets the admin switch to another suggested person, search for someone else, or keep the name as typed, and each row says whether it is "In the directory", "Check the directory suggestion", "More than one option: choose who it is" or "Not in the directory: kept as typed". The linked person's full name and church replace what the sheet had, and the saved row carries `member_id`. Matching ignores accents and titles ("Pr Nairon"), reads a lone letter as an initial ("Mara N.") and only uses the church of the sheet to tell namesakes apart. `suggestMembers` / `searchMembers` in `src/lib/prayerImport.js`, tests in `src/test/prayerImportMatch.test.js` and `src/test/prayerImportDirectory.test.jsx`.
- **Oração 24h › motivos: headings and the rest of markdown** — the text of the prayer intentions now accepts block markdown besides **bold**, *italic* and links: headings (`# Title` … `###### Title`), numbered lists (`1. item`), quotes (`> text`), dividers (`---`), plus `~~strikethrough~~` and `` `code` ``. One line is still one intention (a heading is a line too). It renders on the public board and in the admin preview with real heading elements, never as HTML, and the WhatsApp copy turns headings into bold lines and keeps lists/quotes. Also fixed: a line that started with `**bold**` lost its first star. `parseReasonBlocks`, `reasonsToWhatsApp` in `src/lib/prayerSlots.js`, `ReasonsMarkdown` component.
- **Oração 24h › motivos as an image** — "Baixar imagem" / "Download image" on the public board's intentions box and in the admin (next to "Copiar lista (WhatsApp)") makes a PNG of the intentions (church header, title, circular, dates, the formatted text) to send in the groups: the share sheet on phones, a download elsewhere. `ReasonsImageButton`, reusing `exportImage`.
- **Diretório › Visão Geral** (`/cms`, now the first item) — how the church is distributed, calculated live from the directory: cards (members, churches, groups, families, obreiros, new in 30 days), members **by church** (with M/F), **by age group** and gender, the size of each **assistance group**, a **churches × functions** table (who has how many pastors, deacons, obreiros, louvor, instrumentistas…) and **"O que falta no cadastro"** — people without group, family, church or immigration status and groups without a leader, each one opening the list of who it is. A church filter, a **Visual** (bars) / **Simples** (plain tables) switch and **Baixar imagem / PDF** (A4). **Access by church**: admins and Pr Nairon (a pastor with no limited list) see everything, Pr Jairo only Newark and Philadelphia, Pr Dilton only New York, and a church secretary (clerk) only the church of their account; the Diretório tile is now open to pastors, who get just this page (the other Diretório tools stay admin-only). Churches with nobody registered are left out. Logic in `src/lib/directoryStats.js`; members now carry `createdAt`.
- **Diretório › Membros: filtro por gênero** — new Ambos / Masculino / Feminino switch next to Todos / Membros / Visitantes. It combines with the church, group and member/visitor filters, "✕ Limpar" clears it, and "Exportar CSV" exports only what the filter shows.
- **`FRONTEND_SYSTEM_GUIDELINES.md`**: the frontend rules everyone should follow. It covers color, spacing and type scales, Emil Kowalski's motion curves (`--ease-out: cubic-bezier(0.23, 1, 0.32, 1)` and the others), duration tokens, the reduced-motion path, responsive and tap-target rules, the component reuse table, how the Figma file is used, a PR checklist, and the Impeccable commands to run. It includes a measured baseline from 2026-09-24: production tested at 375/768/1280 px, a motion audit in Before/After format, and the 9 findings from `impeccable detect src`. `DESIGN.md` stays the audit and phased plan.
- **Escalas › Portaria: escala mensal automática** — replaces the manual door rotation. Admins/portaria managers add the workers (searching the directory or typing a name), tick the service days each one can cover (Segunda, Terça, Quarta, Quinta, Sábado, EBD, Domingo) and save. "Gerar escala" then builds any month (current or another): each service gets the chosen number of workers (1-4), only from people who marked that day. The generator fills the hardest services first and avoids repeating a person in the same week or on the same weekday two weeks running, while keeping the load proportional to each person's availability — someone who only marked Wednesday is put on Wednesdays (alternating when others are also free). Services nobody can cover are listed as warnings. The month shows as a calendar; each service can be adjusted by hand (✕ to remove, "+ obreiro" to add), and "Gerar novamente" asks before replacing it. "Publicar" opens the read-only month calendar at `/portaria/YYYY-MM` (alias `/door-schedule/…`; outside `PublicLayout`, list layout on phones), with prev/next month navigation and PT/EN. Generator and calendar helpers in `src/lib/doorSchedule.js` (tests in `src/test/doorSchedule.test.js`).
- **Organograma: desenho e exportação** — besides the tree, tablets and desktops (768px and up) get a **Desenho** view: Área on top, the polos in a row and each polo's churches stacked below, in boxes with the responsible(s) and, per church, one row per function that opens to its names or closes to just the count ("▾ Diácono · 3" / "▸ Obreiro · 8"): **Pastor, Ungido and Diácono start open, Obreiro starts closed**; click any row to flip it, or use **Abrir tudo / Fechar tudo**. The export shows exactly what is open on screen. Phones keep the tree only. **Baixar imagem** and **Baixar PDF** (A4 landscape, fitted) are available on every device and always export the same light, fixed-width sheet with a "Gerado em" date, built off-screen only while exporting; on a phone they open the native share sheet. Export helpers moved to `src/lib/exportElement.js` (shared with the praise list page); PDFs embed a compressed image (about 160 KB instead of 6 MB). The tab counts no longer show "(0)" for "Polos e Áreas" and "Organograma", which have no count. `src/hooks/useWideScreen.js`, `OrgChartDiagram.jsx`.
- **Organograma: responsáveis** — each node shows who is responsible ("Resp. Pr. Nairon Pimentel") and co-responsible ("Co-resp. Pr. Jairo Oliveira"): the Área, each Polo and each Igreja. A responsible is a directory member (shown by their current name, with "Pr." for a Pastor) or just a typed name for someone not registered yet (e.g. Pr. Luiz Laranjeira, Texas). Admins edit them with the pencil next to each node (search a member or type a name, responsible or co-responsible, remove); everyone else reads. Initial data: Área — Nairon; Polo Newark — Nairon; Costa Oeste — Armando; Texas — Luiz Laranjeira; Newark — Nairon (co: Jairo); Philadelphia and Toms River — Nairon; New York — Dilton. New `org_responsibles` table, helpers in `src/lib/orgData.js`.
- **Diretório › Organograma** — a dynamic org chart built on the fly from the directory (nothing is stored): **Área** (title made from the polos, e.g. "Área Newark, Texas e Costa Oeste") › **Polo** › **Igreja** › **função** › people (names and counts), in the order Pastor › Ungido › Diácono › Obreiro, with totals per function. Only the churches of the three polos are in the chart (Atlanta, Ottawa… are left out); a polo church with nobody registered still shows ("Nenhuma função cadastrada"). The four levels are a promotion path, so a person is shown only at the highest one they hold. It follows the directory by itself: a function registered on a member, a church added to a polo or a new polo appears without any change. Visible to admins (Diretório › Organograma) and to the users in `ORG_CHART_USER_IDS` (pastor Nairon, in the Pastor view). Only the ministry levels for now; `buildOrgChart` already takes `scope: "all"` to add GAs, instrumentistas, louvor, secretários… later. "Mostrar nomes" toggle. Logic in `src/lib/orgChart.js`, PT/EN (`org*` keys).
- **Culto Profético › Lista de Louvores (MVP)** — public, PIN-free page `/culto-profetico` (alias `/prophetic-service`; outside `PublicLayout`, so it stays open in maintenance mode) where whoever is typing picks the date and service (EBD / Noite / Outro), fills group, praise leader and "Mensagem" (preacher) as free text, and builds the list of praise songs with one search box for number or title (accent-insensitive; `cl 1` finds `CL-001`). Songs that don't exist yet can be added on the spot (category, optional code, title, theme for Coletânea/CIA); they enter as *pending*, with a warning when a similar title or the same code already exists. The typist's name is required to save and is remembered on the device. After saving, songs can be added, removed and reordered during the service (each change is saved at once). Anyone with the link can keep editing the list (so the task can pass to someone else during the service) until it is published or locks itself at 06:00 the next morning; admins can always edit, lock or unlock. Search results show "Cantado há N dias" for songs sung in the last 90 days; the **Histórico** tab shows every list of any date (lists are kept forever) and the latest dates. Bilingual (PT/EN, `praise*` keys).
- **Lista de Louvores publicada para o Grupo de Louvor** — "Publicar link" opens the read-only page `/culto-profetico/<id>` (alias `/prophetic-service/<id>`) and shows a "Link para o Grupo de Louvor" box (copy / open) right on screen — publishing does **not** close the list: group, leader, preacher and the songs themselves can keep changing (the Praise Group sometimes can't play or sing something and the list changes after the link already went out). A separate **"Finalizar"** action closes the list for editing once the service is really over, independent of the link. The published page: portal look, paper-list layout — "LOUVORES" and "DOMINGO - 02/08/2026", then N° | Nome do Hino (number only — `CL-004` shows as 4 —, or `AVL`/`CIA`/`ENG` for songs without one) — plus the group name only (who led or preached stays internal, not on the sheet sent out). A list that is not published shows "ainda não foi publicada". Admins see "Publicada"/"Fechada" badges (independent of each other) and "Finalizar"/"Reabrir" (lock only, never touches the link) from Escalas › Lista de Louvores.
- **Download/share the published list as image or PDF** — on `/culto-profetico/<id>`, "Baixar imagem" and "Baixar PDF" render the list card (`html2canvas`) and, on a phone, hand it straight to the native share sheet (WhatsApp, etc. via the Web Share API) when supported; otherwise they download the file (`louvores-<igreja>-<data>.png`/`.pdf`). Both libraries (`html2canvas`, `jspdf`, already project dependencies) load on demand via dynamic `import()`, so they never add to the page's initial bundle.
- **Igreja na lista** — each list has a required "Igreja" (Newark, New York, Philadelphia, Toms River first, then every other church of the directory; the last choice is remembered on the device). The published page shows it under "IGREJA CRISTÃ MARANATA" (city only, e.g. NEWARK).

Approving, editing and deleting is limited to admins and the Grupo de Louvor team leader; everyone else sees it read-only.

One person per slot, enforced by the database; trying a taken slot shows "already taken — choose another slot", including when two people race for the same slot. Free slots show an empty circle, taken ones a checkmark with the first name, a colored church label (city) and the rest of the name below in smaller type (nothing is cut off); the person's own slots (remembered per device) can be removed. "Nova lista deste período" duplicates the circular's title/dates/intentions for another list. Use these categories:
- **Added** — new features
- **Changed** — changes to existing features
- **Fixed** — bug fixes
- **Removed** — removed features
- **Security** — security patches
- **Database** — schema changes
